# Step 1 - Add Zustand And Define Store-Owned State Models

## Objective

Install Zustand and create the canonical game state model. This step intentionally does not wrap `PlayerState` or `GameState`. It defines the plain data shapes that will replace them.

## Files To Change

- `package.json`
- lockfile generated by `bun add zustand`
- `src/game/store/types.ts`
- `src/game/store/runStore.ts`
- `src/game/store/roundStore.ts`
- `src/game/store/sceneStore.ts`
- `src/game/store/index.ts`
- `src/game/store/selectors/index.ts`
- `src/phaser/store/subscribe.ts`
- new focused tests under `src/game/__tests__/store/`

## Dependency

Run:

```sh
bun add zustand
```

Use vanilla Zustand APIs:

```ts
import { createStore } from 'zustand/vanilla';
import { subscribeWithSelector } from 'zustand/middleware';
```

Do not use React/Solid hooks for the game store. Solid can consume the vanilla store later if needed.

## Store Ownership Rules

- Store state is plain data.
- Store state does not contain `PlayerState`, `GameState`, Phaser scenes, sprites, containers, sounds, tweens, or textures.
- Actions are the only write path.
- Actions may call pure helper functions, but helpers should return patches/results instead of mutating hidden singletons.
- Use arrays and records instead of `Map` and `Set` in store-owned state.
- Selectors return render models or derived game values, not class instances.

## Define `RunState`

Model everything currently owned by `PlayerState`:

- economy balance
- dice collection
- loaded die target and lucky sync
- spent dice IDs
- equipment instances
- equipment slot count
- consumables
- consumable slot count
- last used consumable ID
- shop slots and shop reroll count
- leg, round, story/endless state
- interest cap
- hand stats as `Record<HandType, HandStats>`
- profession ID and difficulty
- hand size
- purchased permits and current leg permit ID
- permit bonuses/penalties
- trail event modifiers and active round effects
- pending/seen trail event IDs
- skip-shop flag
- trail guide count
- starting dice count
- boss disabled flag and boss round state
- tag queues and skipped-round tag records
- boss assignment IDs
- next die ID
- unlock flags such as dynamite self-destruction

Prefer storing definition IDs over full definition objects when the definition is static data. Example: store `professionId`, not `ProfessionDef`.

## Define `RoundRuntimeState`

Model everything currently owned by `GameState`:

- config
- phase
- day
- rerolls remaining
- total miles
- spent dice snapshot if still needed
- hand dice IDs
- selected-for-roll IDs
- rolled dice IDs and rolled values
- selected-for-score IDs
- current hand type
- hand history
- last score result if needed by UI

Store dice references by ID plus rolled value where possible. The run store owns the dice collection.

## Define `SceneRuntimeState`

Model active scene state that is save/load relevant:

- active scene key
- shop stock, sold flags, packs, opened flags
- booster pack definition ID, contents, picks remaining, used indices, return scene
- trail event ID, resolved flag, spyglass revealed flag
- payout snapshot if needed
- round select transient offers if they are not already in run state

Do not store hover state, active Phaser card objects, drag positions, local graphics, or modal containers.

## Define `UiEffect`

Create a typed queue for one-shot visual work:

- dice added
- equipment destroyed
- equipment created
- consumable animation events
- score animation events if a scene needs to consume them later
- tag earned popups if needed

UI effects are not the state. They describe how Phaser should animate a state transition that already happened or is explicitly staged.

## Store Modules

Create three stores or one root store with slices. Prefer three vanilla stores if it keeps selectors simple:

- `runStore`
- `roundStore`
- `sceneStore`

Each store should export:

- `getState`
- `setState` through typed actions only
- `subscribe`
- reset/hydrate helpers

Avoid exposing raw `setState` outside store modules.

## Phaser Subscription Helper

Create `src/phaser/store/subscribe.ts`:

- `bindStore(scene, store, selector, listener, options?)`
- `bindGameObject(gameObject, store, selector, listener, options?)`

Requirements:

- fire immediately by default
- unsubscribe on scene shutdown
- unsubscribe on game object destroy
- accept optional equality function
- live only under `src/phaser/` because it imports Phaser

## Tests

Add tests proving:

- stores initialize with plain state
- reset returns initial plain state
- hydrate replaces state
- selector subscription fires on action updates
- state contains no `PlayerState` or `GameState` instances

## Done Criteria

- Zustand is installed with `bun`.
- Store modules compile and import no Phaser APIs.
- State models are plain data and ready to replace `PlayerState`/`GameState`.
- Tests cover initialization, reset, hydrate, and subscriptions.
